# `ip2domain` — Scalable Reverse IP to Domain Parser & Network Intelligence

Инструмент и Python-библиотека для поиска доменов, привязанных к IP-адресу или диапазонам IP-адресов (Reverse IP Lookup), сканирования портов Nmap и интерактивной визуализации графа связей.

## 🚀 Особенности (Key Features)

- **Поддержка любых форматов ввода IP**:
  - Одиночный IP: `8.8.8.8` / `1.1.1.1`
  - Подсети CIDR: `1.1.1.0/24`
  - Диапазоны IP: `192.168.1.1-192.168.1.50`
  - Текстовый файл со списком IP/CIDR/диапазонов (`-f targets.txt`)
- **Расширенный Reverse IP**:
  - PTR, HackerTarget, AlienVault OTX, RapidDNS и URLScan.
  - Опционально VirusTotal, Shodan и Censys через API-ключи.
  - Активное извлечение имён из HTTP-заголовков/HTML и TLS-сертификатов,
    включая SNI-варианты виртуальных хостов.
  - Все кандидаты проходят live DNS и wildcard-проверку перед добавлением.
- **Живая верификация (Live DNS Check)**:
  - Включена по умолчанию: устаревшие пассивные записи сохраняются как кандидаты, но в `domains` попадают **только имена, чьи A/AAAA записи сейчас указывают на проверяемый IP**.
  - `--no-verify` отключает фильтр и предназначен только для исследования пассивных данных.
- **Интеграция с Nmap**:
  - Флаг `--nmap`: определяет открытые порты, сервисы и версии на проверяемых серверах.
- **Интерактивный Веб-интерфейс (Web UI)**:
  - Визуализация взаимосвязей (Topology Graph) между **IP-адресами**, **Apex-доменами** и **поддоменами** (на базе Vis.js).
  - Работает на порту `5000` (чтобы не занимать порты 80 и 443 Nginx).
  - DNS wildcard-записи проверяются случайными контрольными именами и не
    создают ложные узлы для несуществующих поддоменов.
  - Для доменных целей автоматически выполняется безопасная попытка AXFR с
    авторитетных DNS-серверов. Отказ transfer не прерывает остальные проверки.
  - Повторное успешное сканирование заменяет старое состояние target/IP в
    общей топологии; сама история запусков при этом сохраняется.
- **Форматы вывода CLI**:
  - Таблица в терминале (`table`), JSON (`-fmt json`), CSV (`-fmt csv`).

## 🌐 Запуск Веб-интерфейса (Web UI)

Для запуска веб-панели используйте флаг `--web`:

```bash
python3 -m ip2domain.cli --web --port 5000
```

По умолчанию панель доступна только локально: `http://127.0.0.1:5000`.

При первом запуске создаётся пользователь `admin`, а сгенерированный пароль
выводится в терминал один раз:

```bash
python3 -m ip2domain.cli --web --host 0.0.0.0 --port 5000
```

Откройте панель и войдите с этими данными. Чтобы задать учётные данные первого
администратора самостоятельно:

```bash
IP2DOMAIN_ADMIN_USERNAME='admin' \
IP2DOMAIN_ADMIN_PASSWORD='replace-with-a-long-password' \
python3 -m ip2domain.cli --web --host 0.0.0.0 --port 5000
```

После создания первого пользователя эти переменные больше не изменяют его
пароль. Пользователи хранятся в `ip2domain.db`; администратор может управлять
ими через `/api/users`.

Для программного доступа при внешнем запуске также создаётся API-токен и
выводится в терминал. При необходимости можно заранее задать постоянный токен
через переменную `IP2DOMAIN_API_TOKEN`.

API принимает токен в `X-API-Key` или `Authorization: Bearer ...`. Приватные,
loopback и link-local цели запрещены по умолчанию. Для доверенной локальной
лаборатории их можно включить через `IP2DOMAIN_ALLOW_PRIVATE_TARGETS=1`.

При работе через HTTPS установите `IP2DOMAIN_SECURE_COOKIES=1`, чтобы браузерная
сессионная cookie передавалась только по защищённому соединению.

### Камеры Centra и Яндекс.Карты

Для карты публичных камер задайте ключ JavaScript API Яндекс.Карт:

```bash
export YANDEX_MAPS_API_KEY='...'
```

Встроенный список содержит пример `I-374-1`. Его можно заменить JSON-массивом
через `IP2DOMAIN_CENTRA_CAMERAS`; у каждой камеры поддерживаются поля `id`,
`title`, `address`, `coordinates` (`[широта, долгота]`), `embed_url` и
`media_info_url`.

Поиск перебирает адреса в формате `I-{ID дома}-{номер подъезда}`. Город для
геокодирования названий из `media_info.json` задаётся переменной
`IP2DOMAIN_CENTRA_CITY` (по умолчанию `Новосибирск`).

### Дополнительные источники Reverse IP

Ключи подхватываются автоматически как в CLI, так и в Web UI:

```bash
export IP2DOMAIN_VIRUSTOTAL_API_KEY='...'
export IP2DOMAIN_SHODAN_API_KEY='...'
export IP2DOMAIN_SHODAN_HISTORY='1'       # необязательно, если тариф поддерживает
export IP2DOMAIN_CENSYS_API_ID='...'
export IP2DOMAIN_CENSYS_API_SECRET='...'
export IP2DOMAIN_URLSCAN_API_KEY='...'       # необязательно, повышает квоту
export IP2DOMAIN_ALIENVAULT_API_KEY='...'   # необязательно
export IP2DOMAIN_HACKERTARGET_API_KEY='...' # необязательно
```

При отсутствии ключа соответствующий платный источник безопасно пропускается.

### Nginx Reverse Proxy (необязательно)
Если вы хотите проксировать веб-интерфейс через имеющийся Nginx на порт 80/443, добавьте в конфигурацию Nginx:

```nginx
location /ip2domain/ {
    proxy_pass http://127.0.0.1:5000/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

## 🛠 Пример использования в консоли (CLI Examples)

### 1. Проверка одного IP с живой верификацией
```bash
python3 -m ip2domain.cli --target 194.33.15.13 --verify
```

### 2. Поиск доменов + Nmap сканирование портов
```bash
python3 -m ip2domain.cli --target 194.33.15.13 --verify --nmap --nmap-ports 80,443,22
```

### 3. Проверка подсети CIDR с экспортом в JSON
```bash
python3 -m ip2domain.cli --target 194.33.15.13/28 --verify --format json --output results.json
```
