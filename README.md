# `ip2domain` — Scalable Reverse IP to Domain Parser & Network Intelligence

Инструмент и Python-библиотека для поиска доменов, привязанных к IP-адресу или диапазонам IP-адресов (Reverse IP Lookup), сканирования портов Nmap и интерактивной визуализации графа связей.

## 🚀 Особенности (Key Features)

- **Поддержка любых форматов ввода IP**:
  - Одиночный IP: `8.8.8.8` / `1.1.1.1`
  - Подсети CIDR: `1.1.1.0/24`
  - Диапазоны IP: `192.168.1.1-192.168.1.50`
  - Текстовый файл со списком IP/CIDR/диапазонов (`-f targets.txt`)
- **Расширенный Reverse IP**:
  - PTR, HackerTarget, AlienVault OTX, RapidDNS и URLScan.
  - Опционально VirusTotal, Shodan и Censys через API-ключи.
  - Активное извлечение имён из HTTP-заголовков/HTML и TLS-сертификатов,
    включая SNI-варианты виртуальных хостов.
  - Все кандидаты проходят live DNS и wildcard-проверку перед добавлением.
- **Живая верификация (Live DNS Check)**:
  - Включена по умолчанию: устаревшие пассивные записи сохраняются как кандидаты, но в `domains` попадают **только имена, чьи A/AAAA записи сейчас указывают на проверяемый IP**.
  - `--no-verify` отключает фильтр и предназначен только для исследования пассивных данных.
- **Интеграция с Nmap**:
  - Флаг `--nmap`: определяет открытые порты, сервисы и версии на проверяемых серверах.
- **Интерактивный Веб-интерфейс (Web UI)**:
  - Визуализация взаимосвязей (Topology Graph) между **IP-адресами**, **Apex-доменами** и **поддоменами** (на базе Vis.js).
  - Работает на порту `5000` (чтобы не занимать порты 80 и 443 Nginx).
  - DNS wildcard-записи проверяются случайными контрольными именами и не
    создают ложные узлы для несуществующих поддоменов.
  - Для доменных целей автоматически выполняется безопасная попытка AXFR с
    авторитетных DNS-серверов. Отказ transfer не прерывает остальные проверки.
  - Повторное успешное сканирование заменяет старое состояние target/IP в
    общей топологии; сама история запусков при этом сохраняется.
- **Форматы вывода CLI**:
  - Таблица в терминале (`table`), JSON (`-fmt json`), CSV (`-fmt csv`).

## 🌐 Запуск Веб-интерфейса (Web UI)

Для запуска веб-панели используйте флаг `--web`:

```bash
python3 -m ip2domain.cli --web --port 5000
```

По умолчанию панель доступна только локально: `http://127.0.0.1:5000`.

При первом запуске создаётся пользователь `admin`, а сгенерированный пароль
выводится в терминал один раз:

```bash
python3 -m ip2domain.cli --web --host 0.0.0.0 --port 5000
```

Откройте панель и войдите с этими данными. Чтобы задать учётные данные первого
администратора самостоятельно:

```bash
IP2DOMAIN_ADMIN_USERNAME='admin' \
IP2DOMAIN_ADMIN_PASSWORD='replace-with-a-long-password' \
python3 -m ip2domain.cli --web --host 0.0.0.0 --port 5000
```

После создания первого пользователя эти переменные больше не изменяют его
пароль. Пользователи хранятся в `ip2domain.db`; администратор может управлять
ими через `/api/users`.

Для программного доступа при внешнем запуске также создаётся API-токен и
выводится в терминал. При необходимости можно заранее задать постоянный токен
через переменную `IP2DOMAIN_API_TOKEN`.

API принимает токен в `X-API-Key` или `Authorization: Bearer ...`. Приватные,
loopback и link-local цели запрещены по умолчанию. Для доверенной локальной
лаборатории их можно включить через `IP2DOMAIN_ALLOW_PRIVATE_TARGETS=1`.

При работе через HTTPS установите `IP2DOMAIN_SECURE_COOKIES=1`, чтобы браузерная
сессионная cookie передавалась только по защищённому соединению.

### Камеры Centra и Яндекс.Карты

Для карты публичных камер задайте ключ JavaScript API Яндекс.Карт:

```bash
export YANDEX_MAPS_API_KEY='...'
```

Встроенный список содержит пример `I-374-1`. Его можно заменить JSON-массивом
через `IP2DOMAIN_CENTRA_CAMERAS`; у каждой камеры поддерживаются поля `id`,
`title`, `address`, `coordinates` (`[широта, долгота]`), `embed_url` и
`media_info_url`.

Поиск поддерживает типы `I` и `G` и перебирает адреса в формате
`{тип}-{ID дома}-{номер подъезда}`. Для `I` автоматически проверяются серверы
`flus1.mycentra.ru`–`flus6.mycentra.ru`,
для `G` — `flus.mycentra.ru`. Город для
геокодирования названий из `media_info.json` задаётся переменной
`IP2DOMAIN_CENTRA_CITY` (по умолчанию `Новосибирск`).
Пользовательский однобуквенный тип можно задать в Web UI вместе с HTTPS-хостом
в домене `mycentra.ru` и отдельным цветом маркеров.
Если хост не указан, для любого типа автоматически перебираются
`flus.mycentra.ru` и `flus1`–`flus6.mycentra.ru`; ручной хост оставляет только
один выбранный сервер.

Для вкладки «Скрины с камер» требуется системный FFmpeg:

```bash
sudo apt install ffmpeg
```

Ручное обнаружение людей на текущих 100 превью использует CPU-модель YOLO11n
через ONNX Runtime. Модель должна находиться в `ip2domain/models/yolo11n.onnx`:

```bash
curl -L -o ip2domain/models/yolo11n.onnx \
  https://github.com/ultralytics/assets/releases/download/v8.4.0/yolo11n.onnx
```

Анализ выполняется одним CPU-потоком и запускается только вручную. Перед
распознаванием кадр старше `IP2DOMAIN_CENTRA_SCREEN_TTL` обновляется; если
свежий кадр получить нельзя, старый не анализируется и камера попадает в список
ошибок. До шести кадров предварительно загружаются параллельно, пока YOLO
последовательно анализирует подготовленные кадры. Размер очереди меняется через
`IP2DOMAIN_CENTRA_PEOPLE_PREFETCH` (1–12); резервный FFmpeg в этом конвейере
всегда ограничен одним процессом. Анализ также
использует два порога: уверенное обнаружение 45% подтверждает наличие людей на
камере, после чего перекрытые и плохо видимые фигуры учитываются при подсчёте с
порогом 10%. Это улучшает подсчёт ночных ИК-камер, не принимая одиночный слабый
шум за камеру с людьми.
назначает кратковременные анонимные ID `person-N` по цветам одежды и внешнему
виду тела, не анализируя лица. Состояние ID хранится в SQLite, поэтому переживает
перезапуск сервиса. ID удаляется только по истечении срока с последнего
обнаружения или кнопкой во вкладке скриншотов. Срок меняется через
`IP2DOMAIN_CENTRA_REID_TTL` (300–86400 секунд). Совпадение является оценкой
визуального сходства, а не подтверждением личности. Для цветных кадров ID
переиспользуется от 98,5% сходства, а для ночных ИК/чёрно-белых кадров — только
от 99,5%, поскольку тёмная одежда разных людей на них выглядит почти одинаково.
Галерея не удерживается в оперативной памяти между камерами: необходимые записи
временно читаются из SQLite для одного сравнения и сразу освобождаются.
В поле поиска вкладки скриншотов можно ввести временный ID, например `person-2`,
чтобы увидеть камеры, на которых он встречался в течение срока жизни ReID.

Кадры берутся из Centra `preview.jpg`; если он недоступен, используется резервное
извлечение из HLS через FFmpeg. Они загружаются лениво: до 12 preview-запросов и
до 4 процессов FFmpeg одновременно. Лимиты меняются через
`IP2DOMAIN_CENTRA_PREVIEW_CONCURRENCY` и `IP2DOMAIN_CENTRA_FFMPEG_CONCURRENCY`.
Кадры считаются свежими 5
минут. Устаревший кадр показывается сразу, а обновляется в фоне. Порог меняется
через `IP2DOMAIN_CENTRA_SCREEN_TTL`. Файлы старше
6 часов автоматически удаляются, каталог ограничен 2 000 JPEG; настройки:
`IP2DOMAIN_CENTRA_SCREEN_RETENTION` (секунды) и
`IP2DOMAIN_CENTRA_SCREEN_MAX_FILES`.
Координаты кешируются в SQLite по адресу. Чтобы защитить дневную квоту Яндекса,
за одно открытие карты геокодируется не более 25 новых адресов; лимит меняется
через `IP2DOMAIN_GEOCODE_BATCH_LIMIT` (0 полностью отключает новые запросы).
Максимальный объём одного поиска Centra задаётся переменной
`IP2DOMAIN_CENTRA_SCAN_LIMIT` (по умолчанию 500 000 комбинаций камер).

### Провайдеры камер

Камеры хранятся в общем каталоге с идентичностью `(provider_id, external_id)`.
Centra подключена через адаптер `CentraProvider`; старые маршруты
`/api/cameras/centra/*` сохранены для совместимости. Доступные адаптеры и их
возможности возвращает `GET /api/camera-providers`, а общий каталог —
`GET /api/camera-catalog`.

Для явно настроенных IP-камер доступен провайдер `generic-ip`. Камеры импортируются
через `POST /api/camera-providers/generic-ip/cameras`; endpoint может иметь тип
`snapshot`, `hls` или `rtsp`. URL обязан содержать IP-адрес без встроенных логина и
пароля. Доступ к частным адресам по умолчанию запрещён общей SSRF-политикой; для
локальной доверенной сети оператор должен явно задать
`IP2DOMAIN_ALLOW_PRIVATE_TARGETS=1`. Кадр доступен по адресу
`/api/camera-catalog/generic-ip/{external_id}/snapshot.jpg`.

Provider-specific протоколы располагаются в `ip2domain/cameras/`, а каталог,
кэш снимков и аналитика не должны зависеть от формата внешнего ID или домена
провайдера. Новый адаптер регистрируется в `ProviderRegistry` и объявляет свои
capabilities; для него не требуется создавать отдельные таблицы камер.

Сканер IP-камер обрабатывает небольшие Nmap-пакеты параллельно. Каждый завершённый
пакет сразу проходит ограниченный общий HTTP fingerprinting; подтверждённая камера
немедленно сохраняется в SQLite и появляется в интерфейсе во время сканирования.
Активное задание можно остановить: сервер завершает работающие Nmap-процессы и
сохраняет уже найденные результаты.
Количество Nmap-процессов автоматически ограничивается числом CPU и доступной
оперативной памятью (резерв 192 МБ на процесс, максимум 12). Верхнюю границу можно
изменить через `IP2DOMAIN_CAMERA_NMAP_MAX_CONCURRENCY` (1–32), а в форме сканера
можно запросить меньшее значение; превысить рассчитанный безопасный лимит нельзя.
Результаты фильтруются в интерфейсе по RTSP, HTTP/HTTPS и ONVIF. Кнопка
«Подключиться» открывает web-интерфейс камеры и RTSP-предпросмотр. Браузер не
поддерживает RTSP напрямую, поэтому свежий кадр извлекается системным FFmpeg с
ограничением `IP2DOMAIN_IP_CAMERA_PREVIEW_CONCURRENCY` (по умолчанию 2) и
пятитисекундным кэшем. Предпросмотр разрешён только для RTSP-порта камеры, уже
подтверждённой сканером и сохранённой в базе.
Для RTSP с HTTP 401 окно подключения принимает логин и пароль. Они передаются
серверу через POST, не попадают в адрес изображения и БД, хранятся только в памяти
до `IP2DOMAIN_IP_CAMERA_SESSION_TTL` секунд (по умолчанию 900) и удаляются при
закрытии окна подключения.
RTSP-путь выбирается в той же форме: доступны `/`, `/live.sdp`, `/h264.sdp`,
`/stream1`, пути Hikvision и Dahua, а также произвольное значение, начинающееся с
`/`. Приложение не перебирает пароли автоматически.
Значение `auto` последовательно проверяет ограниченный список известных путей,
останавливается после первого полученного кадра и запоминает выбранный путь в
текущей сессии. Таймаут одного пути задаётся
`IP2DOMAIN_RTSP_PATH_PROBE_TIMEOUT` (по умолчанию 6 секунд).
Порт `10554` включён в стандартный профиль сканирования. Если у камеры найдено
несколько RTSP-портов (например, 554 и 10554), окно подключения показывает их в
списке и запускает поиск пути на выбранном порту.
Поле потока принимает как отдельный путь, так и полный URL вида
`rtsp://IP/CAM_ID.password.mp2`; URL нормализуется до пути только при совпадении IP
и выбранного подтверждённого порта. `/CAM_ID.password.mp2` также включён в режим
автоматического поиска.
Форма ручного RTSP-подключения предзаполнена значениями `admin/admin`; пользователь
может заменить их перед подключением. Эти значения не используются для
автоматического перебора и не записываются в базу.
После успешного кадра режим «Живое видео» передаёт RTSP в браузер как MJPEG без
звука. По умолчанию используется ширина 640 px, 5 FPS и не более одного
одновременного FFmpeg-потока. Настройки:
`IP2DOMAIN_IP_CAMERA_STREAM_WIDTH`, `IP2DOMAIN_IP_CAMERA_STREAM_FPS` и
`IP2DOMAIN_IP_CAMERA_STREAM_CONCURRENCY` (1–4).
Кнопка «Экспорт CSV» выгружает все сохранённые результаты IP-сканера через
`GET /api/cameras/results/export.csv`. Файл содержит IP, PTR, оценку, уровень
уверенности, обнаруженные протоколы, порты и время обновления.
Одно задание IP-сканера принимает до 262 144 адресов, поэтому диапазон `/15`
помещается целиком. Лимит настраивается через `IP2DOMAIN_CAMERA_MAX_TARGETS`
(1–1 000 000); увеличение лимита не повышает параллельность и, следовательно, не
обходит ограничения CPU и оперативной памяти.
Если Яндекс не вернул координаты, сервер использует DaData. Ключ задаётся только
на сервере через `DADATA_API_KEY`; найденные координаты также попадают в SQLite-кеш.

### Сканер потоков Strix (Strix Stream Scanner)

Интеграция со сканером RTSP/HTTP камер Strix для глубокого обнаружения каналов и потоков видеонаблюдения:

- **Архитектура сервиса**: использует локальный фоновый движок `strix` (по умолчанию `http://127.0.0.1:4567`, настраивается через `STRIX_API_URL`).
- **Параллельность и лимиты**:
  - `IP2DOMAIN_STRIX_FFMPEG_CONCURRENCY` (по умолчанию `3`): максимальное число параллельных процессов FFmpeg для захвата мини-превью кадров.
- **Поддержка пресетов и брендов**: выбор из топ-150 популярных путей камер или специфических профилей брендов (Hikvision, Dahua, Uniview, Beward, XMeye и др.).
- **Поиск по ASN (ASN Range Lookup)**: автоматический поиск всех анонсированных IPv4/IPv6 диапазонов по номеру автономной системы (`AS12958`) через 2ip.io (с решением JS-челленджей) и RIPE Stat.
- **Персистентность и возобновление сканирования**: прогресс сканирования чекпоинтится в SQLite; при перезапуске сервиса активные задачи автоматически возобновляются с текущего IP.
- **Расчет оставшегося времени (ETA)**: динамический индикатор оставшегося времени и скорости сканирования в реальном времени (`IP/с`).
- **Мини-превью каналов**: моментальный захват и кеширование реальных JPG-кадров из найденных RTSP-потоков через `/api/strix/preview`.

### go2rtc (Живой просмотр с минимальной задержкой)

Интеграция со стриминговым сервером go2rtc для прямого воспроизведения RTSP/WebRTC/MSE потоков:

- **Сервис стриминга**: подключается к запущенному экземпляру `go2rtc` (по умолчанию REST API `http://127.0.0.1:1984` и WebSocket `ws://127.0.0.1:1984`, переменные `GO2RTC_API_URL` и `GO2RTC_WS_URL`).
- **Каскадное авто-восстановление источников (Multi-Source Fallback)**: при добавлении потока go2rtc автоматически регистрирует варианты подключения (с авторизацией, анонимно, дефолтный `admin:admin`, каналы `/11`, `/12`, `/1/stream1` и ffmpeg-мост), выбирая работающий источник без ручной правки.
- **Группировка по объектам (IP / Локация)**: потоки с одного IP автоматически группируются в карточки объектов с кастомными названиями и пакетным запуском (`▶ Все` / `■ Стоп`).
- **Система тегов и фильтрации**: быстрые цветные теги объектов (`🏬 ПВЗ`, `🛒 Магазин`, `🏢 Офис`, `🏭 Склад`, `🏠 Дом`, `🚗 Парковка`, `⭐ Избранное`) и живой поиск.
- **Интеграция со Strix**: кнопка «+ Добавить поток» показывает потоки, найденные в Strix для данного IP, с реальными мини-превью кадров и добавлением в 1 клик.
- **Адаптивная сетка**: компактное отображение одиночных камер (до 3–4 в строку) с автоматическим расширением для многопоточных объектов.

### Модульная архитектура (Modular Architecture)

Проект разделен на независимые модули и хранилища:

- **`ip2domain/web/routers/`**:
  - `recon.py`: сканирование реверс-доменов, Nmap и глобальный граф связей.
  - `auth.py`: управление сессиями, токенами и пользователями.
  - `strix.py`: Strix сканер, ASN lookup, управление фоновыми воркерами и чекпоинтами.
  - `go2rtc.py`: проксирование WebRTC/MSE, живые кадры и метаданные камер/групп.
  - `centra.py`: Centra провайдер, DaData/Яндекс геокодинг, YOLO детекция людей и ReID.
  - `cameras.py`: общий каталог камер, Nmap IP-сканер и потоки.
  - `remote_desktop.py`: обнаружение и сканирование RDP / VNC.
  - `modules.py`: HTTP-анализ и детектор уязвимостей.
- **`ip2domain/core/storage/`**:
  - Модульные миксины SQLite (`ReconStorageMixin`, `StrixStorageMixin`, `Go2rtcStorageMixin`, `CamerasStorageMixin`, `CentraStorageMixin` и др.) с единым фасадом `StorageManager`.

### Настройка системного сервиса (Systemd Service)

Для непрерывной работы в фоне и автоматического запуска при загрузке системы используется готовый unit-файл `ip2domain.service`:

#### 1. Установка и регистрация службы:
```bash
sudo cp /root/ip2domain/ip2domain.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable ip2domain
```

#### 2. Команды управления сервисом:
```bash
# Запуск сервиса
sudo systemctl start ip2domain

# Перезапуск сервиса (сканирования Strix продолжатся автоматически с сохраненного IP)
sudo systemctl restart ip2domain

# Остановка сервиса
sudo systemctl stop ip2domain

# Проверка текущего статуса
sudo systemctl status ip2domain

# Просмотр логов в реальном времени
sudo journalctl -u ip2domain -f -n 100
```

> **Примечание по персистентности**: При перезапуске службы фоновые сканирования камер и диапазонов Strix не сбиваются и не теряют прогресс — система автоматически подхватывает чекпоинты из SQLite и возобновляет проверку.

### Дополнительные источники Reverse IP

Ключи подхватываются автоматически как в CLI, так и в Web UI:

```bash
export IP2DOMAIN_VIRUSTOTAL_API_KEY='...'
export IP2DOMAIN_SHODAN_API_KEY='...'
export IP2DOMAIN_SHODAN_HISTORY='1'       # необязательно, если тариф поддерживает
export IP2DOMAIN_CENSYS_API_ID='...'
export IP2DOMAIN_CENSYS_API_SECRET='...'
export IP2DOMAIN_URLSCAN_API_KEY='...'       # необязательно, повышает квоту
export IP2DOMAIN_ALIENVAULT_API_KEY='...'   # необязательно
export IP2DOMAIN_HACKERTARGET_API_KEY='...' # необязательно
```

При отсутствии ключа соответствующий платный источник безопасно пропускается.

### Nginx Reverse Proxy (необязательно)
Если вы хотите проксировать веб-интерфейс через имеющийся Nginx на порт 80/443, добавьте в конфигурацию Nginx:

```nginx
location /ip2domain/ {
    proxy_pass http://127.0.0.1:5000/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```
