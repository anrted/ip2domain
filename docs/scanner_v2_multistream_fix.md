# Исправление проверки камер v2: порты, потоки и превью

Дата: 2026-09-30.

## Результат

Карточка и ключ SQLite остаются привязаны к IP для совместимости API, но внутри
сохраняются отдельные endpoints с портами, производителем, моделью и серийным
номером. Потоки объединяются по полному URL, включая схему, порт, путь и query.
Учётные данные и исходный порт сохраняются у потока; данные одной камеры не
распространяются автоматически на соседние устройства за тем же IP.

* Staged backend читает все страницы inventory, объединяет endpoints до
  сохранения и использует тот же этап захвата, что и обычный scanner v2.
* Ошибки staged/capture не превращаются в успешное завершение задания.
* Обычный backend проверяет порты отдельно, когда несколько портов относятся
  к одной группе сервисов. Один удачный ответ не скрывает соседние камеры.
* По умолчанию проверяются все полученные URL; остановка после первого кадра,
  лимиты 4/8 потоков и общий 40-секундный предел на камеру удалены. Ограничения
  параллелизма и таймауты отдельных запросов/попыток сохранены.
* Пакетная проверка пропускает только конкретный уже проверенный поток с
  читаемым файлом кадра. Другие потоки этого IP продолжают проверяться.
* FFmpeg пишет уникальный временный файл. Успех требует нулевого кода завершения
  и декодируемого изображения. При отмене/таймауте процесс завершается и ожидается;
  временный файл удаляется. Старый JPEG не подтверждает новую попытку.
* ONVIF использует namespace Media и полученный Media XAddr в пределах того же
  хоста. Перебираются все возвращённые Profiles, а не первые 16 произвольных
  XML-атрибутов token. XML-экранирование URI корректно разбирается.
* RTMP определяется по полному S0/S1/S2 с проверкой соответствия S2 клиентскому
  запросу. Отражённый запрос и неполный ответ не считаются RTMP.
* Открытый порт и отсутствие видео не считаются доказательством 401. Ответ
  одного сервиса не помечает все соседние потоки как требующие авторизацию.
* Счётчики показывают подтверждённое видео отдельно от количества URL.
  Картинка привязана к выбранному URL; подстановка кадра соседнего потока и
  кэш по одному IP удалены. Все URL доступны в селекторе; окно потоков показывает
  индивидуальные превью и сведения об исходном устройстве.
* Обновление одного endpoint/потока не удаляет другие порты и потоки из SQLite.

## Проверки

В изолированной временной БД прошли 79 тестов:

```text
tests/test_scanner_v2_multistream.py
tests/test_scanner_v2.py
tests/test_scanner_v2_architecture.py
tests/test_scanner_v2_media_paths.py
tests/test_v2_protocols.py
tests/test_scanner_v2_backends.py
tests/test_scanner_v2_coverage.py
tests/test_inventory_codecs.py
```

Регрессии включают 42 URL одного IP, 30 ONVIF-профилей, несколько RTSP-портов,
пагинацию за пределами 5000 endpoints, отдельные учётные данные, частичные
обновления БД, отмену FFmpeg, неудачный повторный захват и переключение превью
в JavaScript. Дополнительно настоящий FFmpeg успешно получил кадр из локально
сгенерированного FFV1-видео и определил кодек и разрешение 320×240.

В расширенном прогоне остаются три падения вне исправлений камер:

* `test_s7comm_wire_handshake_and_framing`: ожидается `s7comm`, парсер возвращает `iso-on-tcp`.
* `test_bacnet_wire_handshake`: тестовый ответ не проходит валидацию пакета.
* `test_smb_and_rdp_parsing`: тестовый SMB-ответ не проходит валидацию.

Обработчики этих трёх протоколов не изменялись. Проверка синтаксиса JavaScript
выполнена для подключённого bundle и модулей results/player.

## Применение и ограничения

Рабочие БД не мигрировались и не очищались, сервис не перезапускался, внешние
камеры не опрашивались. После загрузки новой версии backend/frontend старые
результаты нужно повторно проверить; заново обнаружить потерянные endpoints
и исправить прежние определения протоколов можно повторным сканированием.

Проверка всех потоков означает все обнаруженные/сохранённые URL. Она не
гарантирует нахождение неизвестных или не объявленных устройством каналов.
Существующие политики и пределы универсального inventory остаются в силе.
Неподдерживаемый тип потока получает `unsupported`, не ложный статус 401.
Проверка многих URL занимает больше времени, поскольку больше не прекращается
после первого успешного кадра.
